품질 관리에 반영했습니다.

배경 / WHY · CONTEXT

사내 규정과 FAQ를 찾는 RAG 서비스

문서에 맞는 검색 방식뿐 아니라 운영 중 쌓이는 피드백의 영향도 고려해야 했습니다. 초기 검색 설정과 이후 품질 관리를 함께 설계했습니다.

문제 / PROBLEM

제목 중심 문서와 오래된 피드백

사내 문서는 제목을 중심으로 구성되어 있었습니다. 한편 오래된 feedback weight가 신규 문서를 밀어내면, 새로 추가된 문서가 검색 결과에 반영되기 어려웠습니다.

가설 / HYPOTHESIS

문서 구조는 반영하고, 과거 평가의 영향은 줄이기

제목 중심 구조를 반영한 chunking이 정답 문서를 찾는 데 적합한지 비교하고자 했습니다. 오래된 평가가 신규 문서를 밀어내는 문제에는 시간에 따른 weight 감소를 설계 방향으로 삼았습니다.

선택 / DECISION

테스트로 chunking을 선택하고, 시간 규칙은 자동화

약 50개 질문의 정답 문서 Top-k 포함 여부를 비교해 제목 기반 chunking을 적용했습니다. 피드백은 평가와 문제 사유를 저장하고, 시간이 지나며 달라져야 하는 weight는 Airflow DAG로 주기적으로 관리하도록 구성했습니다.

구현 / IMPLEMENTATION

검색부터 피드백까지 관리 흐름을 연결했습니다.

  1. 01

    문서 구조와 Chunking

    비교 실험에서 선택한 제목 기반 방식으로 검색용 chunk를 구성했습니다.

  2. 02

    평가와 문제 사유 저장

    평가 값과 함께 문제 사유를 저장해 어떤 피드백인지 확인할 수 있도록 설계했습니다.

  3. 03

    시간 기반 Weight Decay

    과거 평가가 신규 문서를 밀어내는 영향을 줄이기 위해 시간 기반 weight decay를 설계했습니다.

  4. 04

    Airflow 주기 실행

    시간이 지나며 반복해야 하는 weight decay 작업을 Airflow DAG로 자동화했습니다.

검증 / CHUNKING EXPERIMENT

테스트 질문과 Top-k를 기준으로 선택했습니다.

여러 chunking 방식에 대해 정답 문서가 Top-k에 포함되는지를 평가 기준으로 삼았습니다. 테스트 질문 약 50개를 활용한 비교를 바탕으로 제목 기반 chunking을 적용했습니다.

결과와 운영 / RESULT · OPERATION

초기 검색 설정에서 끝나지 않는
품질 관리 구조를 만들었습니다.

Chunking은 테스트 질문으로 비교하고, 운영 중 피드백은 평가·문제 사유와 시간 기반 weight로 관리하도록 설계했습니다. 품질 관리 규칙의 반복 실행은 Airflow로 연결했습니다.
